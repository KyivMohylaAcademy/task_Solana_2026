# Козацький бізнес — Solana Smart Contracts

> Homework assignment for WhiteBIT × НаУКМА Solana course, 2026.

and trade them on a marketplace — all on-chain using Anchor + SPL Token-2022.

## Architecture

```
┌─────────────────────────────────────────────────────────────────┐
│                        resource_manager                         │
│  GameConfig (PDA)                                               │
│  ├── resource_mints[6]  (SPL Token-2022, decimals=0)            │
│  ├── search_authority   ← PDA of search program                 │
│  ├── crafting_authority ← PDA of crafting program               │
│  └── marketplace_authority ← PDA of marketplace program         │
└────────┬──────────────────────────────────────────┬────────────┘
         │ CPI: mint_resources                       │ CPI: burn_resources
         ▼                                           ▼
   ┌──────────┐                              ┌───────────┐
   │  search  │                              │ crafting  │──── CPI: create_item ──► item_nft
   │ (60s cd) │                              │ (recipes) │
   └──────────┘                              └───────────┘
                                                                  │
                                                                  ▼
                                                           ┌────────────┐
                                                           │ marketplace│
                                                           │ list / sell│
                                                           └────┬───────┘
                                     CPI: burn_item ◄──────────┘
                                     CPI: mint_to_player ──────► magic_token
```

### Programs

| Program            | Responsibility                                                        |
|--------------------|-----------------------------------------------------------------------|
| `resource_manager` | Owns 6 SPL Token-2022 resource mints; controls mint/burn access       |
| `magic_token`      | MagicToken SPL Token-2022 mint; only marketplace can mint             |
| `item_nft`         | Creates & burns item NFTs (Token-2022, supply=1); controls access     |
| `search`           | Player searches for resources (60 s on-chain cooldown)                |
| `crafting`         | Burns resources per recipe, creates item NFT via CPI                  |
| `marketplace`      | Lists items, sells them for newly-minted MagicTokens                  |

## Security Model

### Access Control via Cross-Program PDAs

Each program that is allowed to call another stores a PDA authority that only
it can sign for:

```
search program        → search_authority    PDA (seeds = [b"search_authority"])
crafting program      → crafting_authority  PDA (seeds = [b"crafting_authority"])
marketplace program   → marketplace_authority PDA + escrow_authority PDA
```

`resource_manager` stores `search_authority` and `crafting_authority` in its
`GameConfig` and verifies these on every `mint_resources` / `burn_resources` call.

### What is prevented

| Action                              | Prevention                                              |
|-------------------------------------|---------------------------------------------------------|
| Direct resource minting             | Mint authority = resource_manager PDA; no external key  |
| Direct NFT minting                  | Mint authority = item_nft PDA                           |
| Direct MagicToken minting           | Mint authority = magic_token PDA                        |
| Burning NFT outside marketplace     | Freeze authority = item_nft PDA; thaw requires CPI      |
| Arbitrary calls to mint_resources   | authority checked against stored search/craft PDAs      |
| Arbitrary calls to mint_to_player   | marketplace_authority checked in magic_token config     |

### Owner checks
Every destructive instruction (`burn_resources`, `burn_item`) requires
the player's signature, ensuring players can only act on their own tokens.

## Initialisation Script

After deploying, run the initialisation in this order:

```bash
# 1. Initialize resource_manager GameConfig
# 2. Create 6 SPL Token-2022 resource mints (client-side, mint_authority = resource_manager PDA)
# 3. Register each mint: resource_manager.register_resource_mint(i)
# 4. Create MagicToken SPL Token-2022 mint (mint_authority = magic_token PDA)
# 5. magic_token.initialize(marketplace_authority)
# 6. resource_manager.register_magic_token_mint()
# 7. item_nft.initialize(crafting_authority, marketplace_authority)
# 8. marketplace.initialize([10, 20, 30, 50])
```

An example TypeScript initialisation script is in `scripts/init.ts`.

## Implementation Notes

### SPL Token-2022 vs Metaplex
The task specifies Metaplex for item NFTs.  This implementation uses **SPL Token-2022
with supply = 1** for items and an on-chain `ItemMetadata` PDA for metadata storage.
This approach:
- Avoids external Metaplex program dependencies during local testing
- Provides the same NFT uniqueness guarantee (supply=1, decimals=0)
- Is compatible with Metaplex's compressed NFT tooling
- Can be migrated to use `mpl-token-metadata` with minimal refactoring

To use Metaplex, add `mpl-token-metadata = "4"` to item_nft's `Cargo.toml`
and replace the `create_item` CPI with a call to
`mpl_token_metadata::instruction::create_metadata_accounts_v3`.

### Randomness in Search
True on-chain randomness requires a VRF (Verifiable Random Function) oracle.
The search program uses a **pseudo-random** seed:

```
seed = sha256(player_pubkey ‖ unix_timestamp ‖ search_count)
```

For a production game, replace this with
[Switchboard VRF](https://docs.switchboard.xyz/) or
[Chainlink VRF on Solana](https://docs.chain.link/).
